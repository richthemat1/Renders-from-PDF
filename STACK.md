# Стек приложения «Фото из PDF»

Этот файл — основной источник решений о стеке. Версии зависимостей закрепляются в `Исходники/requirements.txt` и `Исходники/frontend/package-lock.json`. Документы с описанием Tkinter относятся к интерфейсу версии 3.14 и совместимому режиму запуска.

## Решение

Обычный запуск версии 3.15 открывает обработку, историю, настройки и просмотр результатов в одном окне Windows: **React + TypeScript + Vite → pywebview → Microsoft Edge WebView2**. Python сохраняет ответственность за PDF, OCR, файлы и транзакции редактирования. Node.js нужен разработчику для сборки интерфейса; пользователю он не нужен.

| Задача | Технология | Причина выбора |
| --- | --- | --- |
| Интерфейс | React 19, TypeScript со строгой проверкой | Общие компоненты и проверяемый контракт с Python |
| Сборка интерфейса | Vite 8 | Локальная статическая сборка без сервера Node в EXE |
| Анимации | GSAP 3, `@gsap/react` | Короткие переходы с очисткой через `useGSAP`; поддержка уменьшения движения |
| Иконки | Lucide React | Единый набор SVG, без загрузок из интернета |
| Состояние редактора | Локальный React state и чистые функции изменений | Изменения локальны до сохранения; отдельный глобальный store пока не нужен |
| Оболочка Windows | pywebview 6.2.1, WebView2 Chromium | Современный CSS и системные диалоги в одном окне |
| Локальный API | Python `ThreadingHTTPServer` на `127.0.0.1` | Повторное использование существующего локального механизма; случайный порт и токен сеанса |
| PDF | pypdf, pdfplumber, pypdfium2, Pillow, ReportLab | Существующая проверенная обработка сохраняется |
| Упаковка | PyInstaller, NSIS | EXE, установщик и переносимый архив |
| Проверки | Python unittest, TypeScript, Vitest, Playwright | PDF и транзакции, модель редактора, сценарии пользователя |

Не добавляем Electron, Next.js, Express, облачную БД или второй PDF-движок: текущим локальным сценариям они не нужны. JavaScript допускается в конфигурации и инструментах; код нового интерфейса пишется на TypeScript. Tailwind и библиотеки компонентов не обязательны: визуальные токены и CSS принадлежат приложению.

## Границы ответственности

- `photo_export.py`, `photo_scan.py` и остальные модули PDF: извлечение, OCR, качество и группировка.
- `photo_edit.py`: проверка ревизии, перестройка PDF, резервная копия, откат и переименование. React не записывает файлы напрямую.
- `photo_state.py`: локальная история и настройки с атомарной записью.
- `photo_jobs.py`: очередь, прогресс и отмена независимо от интерфейса.
- `photo_desktop_server.py`: API приложения и выдача только зарегистрированных результатов.
- `photo_desktop.py`: окно WebView2, системные диалоги, открытие файлов и безопасное закрытие.
- `frontend/src`: экраны обработки, истории, настроек и редактора; поиск, выбор, перенос и порядок изображений.
- `photo_application.py`, `photo_ui.py`, `photo_widgets.py`: совместимый Tkinter-интерфейс, доступный через `--legacy-ui`.

## Данные и безопасность

Обработка остаётся локальной. Интерфейс, шрифты и иконки входят в сборку. API привязан к loopback, случайному токену и проверке Origin для изменений; произвольный путь из веб-страницы не даёт доступ к диску. Файлы выбираются через системный диалог или перетаскивание в родное окно. Сохранение проверяет ревизию отчёта. Результат старого формата открывается из папки с `Отчёт.json`.

`Просмотр.html` сохраняется как переносимый просмотр результата. Основной редактор работает внутри приложения по JSON-отчёту. Миниатюры загружаются лениво; исходные PDF не заменяются миниатюрами. Выигрыш скорости и памяти нельзя обещать без замеров.

## Среда и сборка

Windows x64, Python 3.13, Node.js 24 LTS рекомендуется для разработки. У пользователя необходим WebView2 Runtime; наличие установленного Edge само по себе не является проверкой Runtime. На компьютере без Runtime нужен официальный установщик Microsoft, в том числе автономный для работы без сети. Совместимый Tkinter-режим доступен отдельно и не требует Runtime.

Поддерживаемые Vitest 5 версии Node: 22.12+, 24.x или 26+. На Node 25 npm сообщает `EBADENGINE`; для воспроизводимой среды используйте Node 24 LTS. В текущей среде проверки редактора отдельно выполнены на Node 24.19.0.

Из `Исходники/frontend`: `npm ci`, `npm run dev` для работы над CSS и компонентами, `npm run build` для проверки TypeScript и сборки, `npm test` для модели редактора. Полный интерфейс с файлами проверяется через Python-оболочку; отдельный Vite dev server не получает произвольного доступа к диску.

Из `Исходники`: `.build/venv/Scripts/python.exe -X utf8 -B photo_app.py`, тесты — `.build/venv/Scripts/python.exe -X utf8 -B -m unittest discover`. `build.ps1` собирает frontend и EXE; `build_release.ps1` добавляет проверки, NSIS и архив. Публикация GitHub остаётся отдельным действием через `publish_release.ps1`.

## Дизайн и источник

### Иконка приложения

Единый файл — `Исходники/assets/app-icon.ico`. Он используется при сборке EXE, в окне WebView2 и совместимом окне, в установщике/деинсталляторе, ярлыках и интерфейсе React. Из него перед `npm run build` и `npm run dev` автоматически создаются копия в `frontend/public` и служебный `app-icon.generated.ts`; эти копии не хранятся в Git. При отсутствии ICO интерфейс использует прежний встроенный значок.

Подготовка из нового PNG, ICO или WebP: из `Исходники` запустить `.build/venv/Scripts/python.exe -X utf8 -B photo_icon.py "полный путь к логотипу.png"`. Создаются размеры 16, 20, 24, 32, 40, 48, 64, 128 и 256 px. Исходник не меняется; сохраняются прозрачность и пропорции. После этого обычная сборка подхватит иконку во всех местах.

В версии 3.16 использован предоставленный владельцем `APP_logo.png`, 1254×1254 RGBA. Иконка проверена в собранных EXE и установщике, а также в работающем интерфейсе WebView2.

На 26.10.2026 Figma MCP подтверждает доступ к новому Make-файлу и возвращает ссылки на исходники, но чтение этих ссылок через MCP Resources в текущем клиенте завершается `Unknown resource`. Авторизация аккаунта исправна. Это ограничение получения содержимого, а не подтверждённая ошибка прав файла. Доступный браузерный preview используется для проверки внешнего вида; его нельзя называть чтением исходного TSX через MCP.

EXE, установщик и ZIP версии 3.15 собираются в `Релизы/3.15`. Сам EXE проверен с WebView2: обработка PDF, открытие результата внутри окна, перенос нескольких изображений, сохранение и резервная копия. В PATH дочернего процесса отсутствовали Python и Node; внешние запросы самой страницы не наблюдались. Проверки на чистой виртуальной Windows пока не проводились. Выпуск на GitHub выполняется штатным `publish_release.ps1`: чистая ветка main, полная сборка и проверки, аннотированный тег от richthemat1, атомарная отправка main и тега, четыре файла релиза и отметка Latest.
